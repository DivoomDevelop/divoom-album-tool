# v0.3.4 原照片比例与 JPG 方向修正（2026-10-20）

修正竖拍 JPG 的 EXIF 方向未计入宽高，导致预览和 WebP 导出被拉成横图的问题。读取 JPEG APP1/TIFF 方向标签，支持大小端和全部八种方向，缺失或不完整元数据安全回退；FFmpeg 和浏览器继续各自只应用一次拍摄方向。预览信息缓存更换版本键，原文件保持不变。

照片的全部模式、旋转、缩放裁剪及首张批量模板保持原照片比例，导出尺寸允许变化，且宽高均不超过设备实际尺寸。宽度/高度适配明确用于编辑视图缩放，溢出部分可滚动查看，导出保留原图比例；相同宽高上限下完整照片的导出尺寸可相同。视频仍按设备比例裁剪。

- 自动测试 33 项通过；方向用大小端各 8 种 JPEG 实际转换校验，圆形图案不得拉伸，并覆盖损坏 EXIF、奇数源图、四边颜色、不同设备尺寸及批量模板。
- 用户提供的两张 JPG：显示尺寸分别为 2448×3264 和 3264×2448；三种模式、1 倍/2 倍裁剪共 12 次实际导出通过，对 800×1280 设备分别输出 800×1066 和 800×600。转换前后原文件 SHA-256 一致。
- 实际 Tauri/WebView2 与随包 worker、本地 HTTP 设备测试服务：用这两张原图验证 19 种语言、最小窗口、适配切换的实际视图尺寸变化、旋转/重置、首张模板和单张调整、批量预览；完成真实转换和 multipart 上传及两相簿回读确认。PhotoWidth/PhotoHeight 与文件一致，PhotoTitle 为空。切换 480×480 设备后照片仍保持 4:3 导出 480×360；视频只显示视频裁剪流程。

本轮上传验收使用本地设备测试服务，未向真机写入这些私人照片，也未刷写固件。用户照片、路径及截图只留在本机验收目录，不随发布包或 GitHub 源码上传。TimesFrame 固件支持状态沿用 v0.3.2；macOS 未在本机打包验证。
